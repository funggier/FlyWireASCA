# Work from goals to completion

Think in outcomes, evidence, dependencies and decisions. Adapt the process to the work; preserve continuity and complete the authorized outcome.

## Establish the brief

Record the outcome, scope, constraints, success criteria, existing approvals and remaining gates. Treat later messages as steering the active goal unless the user replaces it. Separate facts from assumptions. Ask only for information that changes a material decision; continue independent work while waiting. Apply higher-priority instructions and relevant domain skills.

## Establish current truth

Read a specifically required handoff first, then inspect current sources before acting. Match the actual environment and artifact identity: repository/branch/runtime, document revision, dataset or operational record. Investigate discrepancies and explain their effect. Preserve historical evidence with its original conclusions; record corrections separately. Label unavailable evidence as unknown.

## Scale the plan

| Work | Useful preparation |
|---|---|
| Clear, reversible task | Brief approach and observable completion check |
| Several linked steps | Ordered tasks, dependencies, checkpoints and acceptance criteria |
| Architecture, migration or consequential redesign | Trade-offs, detailed design, reviewable specification and implementation plan |
| Research or comparison | Question, comparable inputs, measures, frozen evaluation where applicable |

Follow the user's and project's actual approval gates. Bind each approval to the artifact and stage reviewed. Resume at the earliest incomplete gate. Reuse established choices and approvals; prepare concrete results before requesting a final authorization. Keep routine decisions inside approved scope moving.

## Execute and adapt

Use the selected execution method. Work in dependency order, with bounded steps and meaningful verification. Keep a compact ledger for sustained work: authority/version, completed work with evidence, decisions and trade-offs, unresolved items, current step and next action. After interruption, recheck live state before repeating a mutation.

Choose subagents when independent work or a fresh review improves quality or elapsed time enough to justify coordination. Give each a clear outcome, source artifacts, ownership, constraints and return contract. Parallelize independent work; sequence dependencies and shared mutations. Integrate and verify their findings as the responsible owner. Read [delegation.md](references/delegation.md) when delegating.

If evidence changes the approach, explain the finding and revise the remaining plan. If scope changes beyond approval, prepare the changed design for review while continuing independent authorized work. Avoid stopping at an ordinary checkpoint when more approved work remains.

## Verify and deliver

Check the actual result against success criteria using suitable readback, tests, calculations, sources or observation. Distinguish attempted, verified, unknown, failed and approved states. Report separate quality and cost measures; retain negative results. Read [adaptation.md](references/adaptation.md) for domain checks and a handoff recipe.

Produce one coherent deliverable: outcome first, artifact, verification, then unresolved gate and next action if any. Reuse evidence references instead of duplicating tables and status summaries. Keep progress updates concise and useful. Deliver the authorized work; publishing, sending or deployment follows the user's authorization.
